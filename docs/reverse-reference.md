# Local Horizon implementation reference

`tools/reverse.py` creates a searchable reference from the already-extracted OTA.
Generated bytecode and native data stay in ignored `work/reverse/`. The tool reads
original `work/fs` files and does not modify the emulator, APKs, or framework jars.

```powershell
python tools/reverse.py build
python tools/reverse.py search CoreFunctions --kind class
python tools/reverse.py search Head --kind symbol --source trackingserviceclients
python tools/reverse.py search MemoryBroker --limit 40
python tools/reverse.py disassemble /system_ext/lib64/libtrackingserviceclients.so --symbol Head
python tools/reverse.py disassemble /odm/lib64/libhzos_trackinghost.meta.so --symbol HostConnection
```

The build uses the existing Java/baksmali tooling and pure-Python DEX/ELF readers.
Native disassembly additionally uses `capstone`, which is installed in this
workspace's Python environment. No NDK is needed. Search results include the
original device path, DEX entry or ELF string offset, and the generated artifact.
`manifest.json` records content hashes and any processing failures.

The reference includes Meta classes from the system framework, all classes from
selected system_ext framework jars, VrShell, VrDriver, CMSHeadset, and
PresenceService. Native coverage is 64-bit libraries whose filenames contain
tracking, memorybroker, runtimeipc, compositor, or sensor. It is deliberately
focused rather than a dump of every app in the OS.

Java output is smali disassembly with method bodies, constants, Binder Stub/Proxy
code, and native declarations. Native output includes imports, exports,
dependencies, strings, and optional assembly for matching exported functions.
Neither output reconstructs original Java/C source. Native assembly retains ELF
addresses and does not resolve branch targets or discover unnamed functions.

## Useful findings for the implementing agent

### Presence already contains CoreFunctions

The original PresenceService APK defines
`Lcom/facebook/simplejni/CoreFunctions;` in `classes.dex`. VrShell defines it too.
Presence's `classes2.dex` includes callers such as `X/2gE` that invoke
`Class.forName("com.facebook.simplejni.CoreFunctions")` before loading native code.
Therefore the earlier `ClassNotFoundException` is not enough evidence that the
OTA is missing this class. Compare the deployed APK's hashes/DEX entries with
the original and capture the full exception chain and class loader context.
Inspect class initialization and native loading as well as packaging.

Entry points:

- `work/reverse/java/PresenceService.apk-c2b599c267/classes/smali/com/facebook/simplejni/CoreFunctions.smali`
- `work/reverse/java/PresenceService.apk-c2b599c267/classes2/smali/X/2gE.smali`

### TrackingInjection has a misleading pose API

`com.oculus.os.TrackingInjection` loads `controllers_jni` and checks
`persist.ovr.enabletrackinginjectionsdk`. However, its public
`updateHeadsetPoseField` and `updateRemotePoseField` implementations throw
`UnsupportedOperationException` stating that the operation is no longer
supported. Inspect those bodies before investing in this
API for head/controller pose injection. MemoryBroker/shared-memory work remains
a more concrete path for the current build. Button/thumbstick injection has
native declarations, but has not been runtime-tested here.

Entry point:
`work/reverse/java/com.oculus.os.platform.jar-11ccee9487/classes/smali/com/oculus/os/TrackingInjection.smali`.

### Binder contracts are available locally

`com.oculus.os.platform.jar` contains interfaces such as
`oculus.internal.power.IVrPowerManager` and their Stub/Proxy implementations.
Use the generated `TRANSACTION_*`, `onTransact`, and Parcel reads/writes to
recover exact transaction layouts instead of guessing them from service names.

```powershell
rg -n 'TRANSACTION_|onTransact|writeInterfaceToken' work/reverse/java
```

## Validation

The initial successful build indexed 729,405 rows across 81 source units with
zero reported processing errors. Searches located actual CoreFunctions class
definitions in both APKs. Capstone generated assembly for six exported head
tracking functions in `libtrackingserviceclients.so`. These are static-analysis
findings; no emulator deployment or runtime behavior was tested.
